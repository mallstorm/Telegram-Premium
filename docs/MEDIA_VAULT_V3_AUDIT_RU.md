# Медиатека V3 и YouTube: сравнение с V2

Сравнение с исходным состоянием 13.1.1 до правок Vault (`4e497ad`, удалённый исходный коммит `2c8a895`) показало: сами классы медиатеки, плеера и YouTube в предыдущих исправлениях не менялись. Изменился backend каталога: вместо открытого JSON V2 теперь требуется расшифровать V3 и открыть защищённую сессию.

Подтверждённые проблемы:

- Медиатека читала только `UserConfig.selectedAccount`, а экран облака умеет показывать файлы других аккаунтов. Выбор аккаунта в облаке не равен глобальному выбранному Telegram-аккаунту.
- Отдельная Activity медиатеки не показывала графический ключ/биометрию перед чтением V3. Ошибка доступа приводила к пустому списку. На возвращении в Activity список не обновлялся.
- Старый поисковый запрос сохранялся при переключении источника и мог скрыть все новые файлы.
- Плеер оставлял старый источник работающим во время получения нового. При ошибке нового источника старый плеер не освобождался; его позиция могла записываться уже для нового видео.
- Поиск радио по одной букве зацикливал `loadRadio` и `runRadioSearch` на UI-потоке. HTTP радио выполнялся в общей `Utilities.globalQueue`, задерживая в том числе криптографические задачи облака.
- Отменённые запросы YouTube продолжали занимать очередь. Соединения не закрывались гарантированно при исключениях.
- Использовался NewPipe Extractor 0.26.5. В выпуске 0.27.0 от 7 ноября 2026 удалены сломанные клиенты YouTube и изменён механизм получения потоков. Требование LOGIN_REQUIRED приходит от YouTube; библиотека не требует обязательного подключения Google-аккаунта. Ограничения конкретного IP/VPN или ролика могут остаться и после обновления.

Изменения: общий V3-каталог CloudManager, все подключённые аккаунты и явный фильтр, обновление при возвращении, разблокировка штатным графическим ключом/биометрией, очистка защищённого списка при блокировке. Плеер немедленно освобождает старый источник, отменяет устаревшие HTTP-запросы и проверяет привязку пользователя/поколения облака/документа. Потоковая расшифровка сохраняет проверку AES-GCM и не переводится на V2. Добавлены проверки чтения и перемотки реальных зашифрованных частей, повреждений, смены аккаунта/сброса и отмены запросов. NewPipe обновлён до 0.27.0; обязательного входа Google не добавлено.

Проверено локально: 56 новых проверок production-классов: 38 для каталога, поточного источника и отмены; ещё 18 для контроллера плеера (остановка старого звука, корректная позиция продолжения, отмена, устаревшие ответы, пауза во время загрузки, неизлечимая ошибка аутентификации отменённая повторная попытка сети и различение TLS/ошибки Vault). Всего с прежними тестами — 290 проверок. Обёртка YouTube компилируется с NewPipe 0.27.0. Реальные сетевые пробы старой и новой версии не выполнены: автоматическая проверка разрешений остановилась из-за лимита использования, не вынеся решения о безопасности. Проверка на телефоне и полная новая Android-сборка остаются необходимыми.

## Проверка на телефоне после установки

1. Установить APK 723739 поверх текущего приложения. Повторный сброс облаков не нужен.
2. Открыть **Медиа → Облако → Все аккаунты**. При запросе ввести существующий графический ключ или подтвердить биометрию. Переключить вкладки музыки/видео; уже загруженные в V3 файлы должны появиться. Кнопка обновления повторно читает каталог; фильтр аккаунта позволяет проверить каждый источник отдельно.
3. Воспроизвести загруженную музыку и оба видео, проверить перемотку и переключение на файл устройства. Проверить, что прежний источник перестаёт звучать сразу при выборе нового.
4. В радио ввести одну букву, затем полный запрос; переключить источник во время поиска. Экран не должен зависать, поздние результаты не должны заменять выбранный список.
5. В YouTube открыть ролик из ранее добавленного канала. Если YouTube по-прежнему возвращает проверку бота, проверить тот же ролик в браузере и на другой сети/VPN. Обновление экстрактора не снимает ограничения YouTube для адреса сети.

Существующие Master Key, код восстановления, служебные каналы и файлы не пересоздаются этой сборкой.
