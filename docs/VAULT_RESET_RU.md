# Пересоздание зашифрованных облаков всех подключённых аккаунтов

Сборка 723729 (13.1.1) добавляет действие **Настройки → Защита облака → Пересоздать облака всех аккаунтов**.

1. Приложение читает список каналов всех подключённых Telegram-аккаунтов, включая архив и закреплённые диалоги. Показывает имена и ID аккаунтов, названия и ID служебных каналов.
2. Пользователь на телефоне подтверждает удаление конкретного списка. Все файлы в удалённых каналах теряются навсегда. Код восстановления не восстанавливает удалённые Telegram-вложения.
3. Перед каждым удалением повторно проверяются владелец, тип канала, название и описание. Удаляются только собственные broadcast-каналы с меткой `TELEPREMIUM_CLOUD_STORAGE_V2`, `TP_VAULT_V3` (включая метку операции) либо сохранённой локальной привязкой. Совпадение одного названия недостаточно. Обычные чаты, группы и «Избранное» целиком не удаляются.
4. Подтверждения удаления сохраняются. Ошибки сети, FLOOD_WAIT или изменение канала приостанавливают операцию. Для продолжения используется **Продолжить пересоздание облаков**. Подтверждённые удаления не повторяются; потерянное подтверждение требует полной проверки отсутствия канала на сервере.
5. Новый общий Master Key создаётся только после всех подтверждений и очистки старых каталогов/очередей выбранных аккаунтов. Прежние обёрнутые AndroidKeyStore ключи сохраняются локально в зашифрованном архиве; независимые зашифрованные реплики без привязки к аккаунту не уничтожаются. Новый каталог их не импортирует.
6. Для каждого уникального подключённого пользователя создаётся новый приватный V3-канал с меткой операции и отправляется зашифрованный пустой каталог. Успех показывается после подтверждения синхронизации каждого аккаунта. Повторный запуск этапа создания не меняет ключ и не удаляет новые облака.
7. Сохраните **новый код восстановления** вне Telegram. Старые коды не открывают новые облака. На других устройствах потребуется новый код; сброс не заменяет их локальные ключи автоматически.

Смена состава подключённых пользователей требует вернуть исходные аккаунты перед продолжением. Повторный просмотр может включить новые служебные каналы только после нового явного подтверждения. Удаление не запускается установкой обновления или открытием настроек.

Загрузки и операции каталога привязаны к сохранённому поколению состояния и Telegram ID. Поколение меняется до удаления и перед созданием, поэтому старые ответы не восстанавливают очищенные очереди, каталоги или привязки. Очистка ограничена каталогами приложения, не проходит по символическим ссылкам и не затрагивает исходные файлы пользователя.

Проверки: реальные криптографические операции AES-GCM и AndroidKeyStore через тестовый провайдер; production-классы сброса, сканера, выбора канала и индекса с детерминированным Telegram-сервером. Тесты не обращаются к реальным Telegram-аккаунтам и ничего в них не удаляют. Проверка на реальном телефоне выполняется пользователем после установки APK.

## Проверка сборки 723729

224 проверки: CloudCore 19, PlayerAndFormat 31, VaultCrypto 65, VaultFileOps 9, VaultKeyManager 36, IndexRuntime 23, PeerRuntime 13, CloudReset 28. Синтаксис 159 Java-файлов проверен; overlay содержит 304 файла.

GitHub Actions не стартует: Annotations сообщает о неудачных платежах либо ограничении расходов аккаунта. Локальная Android-сборка использует JDK 17, SDK 36 и задачу `:TMessagesProj_App:assembleAfatRelease`. Java/Kotlin, ресурсы и DEX собираются из новых исходников. Нативная `libtmessages.49.so` берётся без изменений из предыдущего подписанного APK 723719: в этой работе нативный код не менялся. Остальные зависимости, настройки Telegram API и сертификат соответствуют предыдущей сборке. Проверки подписи, версии и SHA-256 выполняются для готового APK. На телефоне операция удаления ещё не проверена.
