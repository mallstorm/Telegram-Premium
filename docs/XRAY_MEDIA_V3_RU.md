# Xray, навигация и медиатека V3 — 13.1.1 / 723749

## Маршруты

Откройте профиль аккаунта → сетевой профиль → Xray. Импортируйте до десяти ссылок или конфигурацию, поддерживаемую конвертером libXray. В списке аккаунтов назначьте каждому свой профиль. Один профиль можно использовать для нескольких аккаунтов. Передача файлов V3 следует маршруту Telegram-аккаунта, которому принадлежит облако.

У публичной медиатеки отдельный выбор: напрямую, Xray выбранного аккаунта или конкретный профиль. Он действует на YouTube, радио, IPTV, загрузки и обложки. Это встроенный транспорт клиента, а не системный VPN; трафик других приложений не перенаправляется. Вызовы Telegram и встроенные веб-страницы не обещаются через этот транспорт. При переключении аккаунтов режим «Xray текущего аккаунта» меняет маршрут сетевого плеера; если у аккаунта Xray не назначен, этот режим использует прямое соединение, как указано в названии. Для постоянного маршрута выберите конкретный профиль.

Один экземпляр ядра обслуживает отдельные SOCKS/HTTP входы на loopback для каждого профиля. По умолчанию неназначенный вход блокируется. При отказе выбранного профиля прямой запасной маршрут не включается. Локальные IP-сети можно явно исключить в настройках профиля. Доменные назначения передаются выбранному outbound без локального разрешения в HTTP-прокси; разрешение адреса самого сервера зависит от Android и типа транспорта. Полные конфигурации нормализуются в независимые outbounds: чужие inbound, routing, proxySettings и dialerProxy не принимаются. Старые VMess-ссылки в формате JSON/base64 могут требовать преобразования в современный формат или JSON-конфигурацию.

Секреты профилей хранятся локально через AndroidKeyStore/AES-GCM. В синхронизацию медиатеки они не включены. Потеря локального ключа устройства требует повторного импорта профилей. Если Android вернул нечитаемую резервную копию профилей, экран Xray предлагает явный сброс локального списка с сохранением исходного зашифрованного архива. Он не удаляет ключи Vault и медиатеку; переход публичной медиатеки напрямую указан в подтверждении. Аккаунты с отсутствующими профилями остаются закрыты до явного выбора нового маршрута.

## Интерфейс

Нижняя панель: Чаты, Контакты, Облако, Медиа, Профиль. Настройки остаются в меню профиля. Облако и медиатека открываются внутри главного экрана.

Картинки облака открываются во встроенном полноэкранном просмотрщике, поддерживают свайпы, масштабирование и подгрузку соседней картинки. Видеофайлы открываются с очередью видимых видео текущей папки/фильтра: центральные предыдущая/следующая переключают файл, боковые кнопки перематывают время.

Список YouTube-каналов имеет поиск, добавление, переименование и удаление отдельных строк. Требования YouTube к авторизации определяются сервером; наличие Xray не гарантирует воспроизведение без входа для заблокированных сервером запросов.

## Синхронизация

В медиатеке нажмите статус синхронизации, чтобы выбрать облако одного из подключённых Telegram-аккаунтов. Библиотека закреплена за постоянным Telegram user ID, а не за номером позиции аккаунта. Явная смена облака переносит текущую библиотеку в выбранное облако; прежняя копия автоматически не удаляется.

Каналы YouTube, IPTV, избранное радио, плейлисты и настройки качества/сортировки/эквалайзера/очереди сохраняются внутри зашифрованного каталога V3. Удаления записываются отдельными отметками, поэтому старое устройство или запоздавший ответ YouTube не возвращают удалённый канал. Повторное добавление пользователем разрешено. Изменения без сети сохраняются на устройстве до следующей успешной синхронизации.

Локальные URI файлов и разрешения Android не переносятся на другое устройство. Для импортируемого M3U до 4 МиБ сохраняется сжатое содержимое; старый импорт преобразуется при открытии медиатеки, пока разрешение чтения ещё действует. Плейлисты с файлами устройства сохраняют метаданные и привязываются при сканировании только к совпадающим файлам. Сами видео и аудио устройства не загружаются этой функцией. Ссылки на V3-файлы привязываются к актуальному каталогу по user ID и node ID.

После переустановки подключите тот же Telegram-аккаунт и восстановите **исходный ключ V3 кодом восстановления**. Автоматически созданный новый ключ не расшифрует старую библиотеку. При блокировке защиты облака синхронизация приостанавливается до разблокировки. Открытая библиотека проверяет изменения примерно каждые 45 секунд, собственные изменения отправляются с короткой задержкой; вход в аккаунт и повторное открытие медиатеки также запускают синхронизацию.

## Происхождение и размер ядра

Официальный релиз: https://github.com/XTLS/libXray/releases/tag/v26.10.31 . Из Android AAR удалены все ABI, кроме arm64-v8a. Сам libgojni.so сохранён побайтово; SHA-256 и размеры зафиксированы в TMessagesProj/libs/libXray-26.10.31-arm64.json, исходный ZIP SHA-256 fb99f04acf379cc2957c1e1d0ce2b3c0005d3f49974a44c09a11242a0562c1ca. Нативный SHA-256: 8631d224895f7bee39389dad064e9baa8a5381855e03e60a739665dcda070f0e. Лицензии MIT libXray и MPL-2.0 Xray-core находятся в assets/telepremium/licenses. Версия Linux из того же релиза используется только в тесте маршрутов, в APK не входит.

Release использует R8 и удаление неиспользуемых ресурсов. Оставлены узкие правила JNI для go.** и libXray.** по тому же принципу, что в GitHubble. Проверка адресов, портов и структуры маршрутов выполняется до остановки действующего ядра. Полная нативная testXray разрешена самой библиотекой только без работающего managed-ядра; при активных маршрутах импорт проверяет структуру, а полная загрузка выполняется при переключении. Все профили используют один экземпляр ядра: изменение набора назначенных профилей кратковременно перезапускает его.

Нативное Go-ядро R8 не уменьшает: arm64 AAR добавляет около 11,8 МБ сжатых данных. Базы geoip/geosite и остальные ABI в приложение не добавлены. Фактический итоговый размер фиксируется после сборки.

## Проверки

Набор проверок проверяет реальную модель синхронизации и сохранение через AES-GCM, включая переустановку, офлайн, удаление, повторное добавление, потерю Keystore при Android backup и замену аккаунта в позиции. Тест официального Linux-ядра проверяет два одновременных независимых маршрута, отказ без прямого переключения, десять профилей и освобождение портов. Проверка AAR контролирует SHA-256, единственный ABI и ELF-сегменты с выравниванием 16 КБ.

Android-компиляция и signed release подтверждают совместимость исходников и упаковки. Проверка на физическом телефоне и с пользовательскими прокси остаётся отдельным этапом.
